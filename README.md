# Mini-TMS — мобильная CAT-система (по ТЗ)

CAT (Computer-Assisted Translation) система: организации с изоляцией данных,
проекты и задания с полным жизненным циклом, память переводов (TM),
терминологические базы (TB), машинный перевод (MT), контроль качества,
пред-перевод и анализ объема (леверидж TM), двуязычная выгрузка для ревью,
уведомления и мультиаккаунтность. Реализовано по ТЗ (`ТЗ САТ.txt`); матрица
соответствия — ниже.

## Компоненты

```
┌────────────────────┐   ┌────────────────────┐
│ Web-клиент (React) │   │ Mobile (Expo RN →  │
│ PM + переводчик    │   │ APK для Android)   │
│ + Desktop (Tauri,  │   │                    │
│ win64/macOS)       │   │                    │
└─────────┬──────────┘   └─────────┬──────────┘
          │ REST (JWT + X-Org-Id)  │
          │ WebSocket /ws/updates  │
          ▼                        ▼
┌────────────────────────────────────────────┐
│ FastAPI: auth/orgs/projects/jobs/tm/tb/    │
│ notifications; сервисы QA, MT, тегов,      │
│ сегментации, экспорта, напоминаний, аудита │
└───────────────────┬────────────────────────┘
                    ▼
         SQLite (SQLAlchemy) + файлы документов в data/
```

- **Роли** (на уровне организации): `admin`, `pm`, `translator`; один пользователь
  может состоять в нескольких организациях с разными ролями. Доступ проверяется
  на сервере: заголовок `X-Org-Id` + membership; все выборки фильтруются по org_id.
- **Жизненный цикл задания** (§7 ТЗ): unassigned → assigned → accepted →
  in_progress → submitted → completed / rework → … → canceled. Просрочка —
  вычисляемый признак, не статус.
- **Прогресс** (формула ТЗ): подтвержденные обязательные сегменты / все
  обязательные × 100%. Прогресс 100% не заменяет действие «Сдать задание».

## Веб и десктоп

Система доступна в трех видах из одного кода веб-клиента:

1. **Веб-версия одним URL**: FastAPI раздает собранный SPA — запустите сервер
   и откройте `http://<сервер>:8000` (роуты `/api/*` и `/ws` имеют приоритет,
   остальные пути отдают `index.html`). Отдельный статик-хостинг не нужен;
   при желании `web/dist` можно выложить куда угодно и задать `VITE_API_BASE`.
   Адрес сервера также вводится на экране входа (хранится в localStorage) —
   это позволяет одной сборке работать с любым сервером.
2. **Windows x64**: установщики (NSIS `-setup.exe` и `.msi`) собираются в CI
   и публикуются на странице **Releases** (`Mini-TMS-CAT_0.2.0_x64-setup.exe`);
   исторические сборки 0.1.0 — в `desktop-builds/`. Пересборка локально:
   `desktop\build.cmd` (см. нюансы тулчейна ниже). Требуется только WebView2
   (есть в Windows 10/11).
3. **macOS (dmg, universal — Intel + Apple Silicon) и Linux (AppImage/deb)**:
   собираются в GitHub Actions (workflow `desktop-builds`) и при пуще тега `v*`
   публикуются на странице Releases; без тега — артефакты прогона
   (Actions → desktop-builds → Run workflow). Сборка без подписи — при первом
   запуске macOS: правый клик по приложению → Open.

Локальная сборка Windows (Tauri 2 + GNU-тулчейн) требует полного MinGW:
на этой машине он собран в `C:\Users\dolme\tools\mingw-ucrt` из пакетов msys2
(binutils, gcc, gmp/mpfr/mpc/isl, zlib/zstd/gettext/libiconv, libgcc, libstdc++,
libwinpthread — зеркало TUNA). Линкер — self-contained gcc из rustup
(`CARGO_TARGET_X86_64_PC_WINDOWS_GNU_LINKER` в `desktop\build.cmd`), т.к. у
msys2-gcc нет CRT-импорт-либ (mingwex/kernel32). CI собирает через MSVC — там
эти шаги не нужны.

## Запуск

### 1. Сервер (Python 3.12+)
```bash
cd backend
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt      # Linux/macOS: .venv/bin/pip
.venv/Scripts/python -m uvicorn app.main:app --port 8000
.venv/Scripts/python -m pytest tests/ -q           # 88 тестов: §12 + QA/TMX/конкорданс/CJK + леверидж + LQA/TBX/комментарии + биллинг/история/отчеты + локи/RX-QA + обратная связь + псевдо-перевод/хендофф/выравнивание/внешние уведомления
```
Swagger: http://localhost:8000/docs. Первый запуск создает БД и демо-данные:
- организация **Demo Org**, пользователи `admin/admin123` (org admin),
  `pm/pm123`, переводчики `ann/ann123`, `ivan/ivan123`;
- TM «Demo TM» (en→ru), TB «Demo TB» (с preferred/forbidden терминами),
  прайс-лист «Standard EN→RU» (EUR, ставки по категориям, минимальная сумма 15);
- проект «Marketing Brochure» с документом и заданием, назначенным на ann.

Env-переменные: `TMS_SECRET_KEY`, `TMS_DATABASE_URL`, `TMS_DATA_DIR`,
`TMS_MT_PROVIDER` (`none|libretranslate|mock`), `TMS_MT_URL`, `TMS_MT_API_KEY`,
`TMS_FUZZY_MIN_SCORE`, `TMS_ANALYSIS_*` (веса котировки), `TMS_LQA_*`
(штрафы minor/major/critical и порог приемки LQA-оценки), `TMS_RATE_CURRENCY`
(валюта новых прайс-листов по умолчанию), `TMS_SEGMENT_LOCK_TTL` (TTL лока),
`TMS_QA_REGEX_MAX_PATTERN`; внешние уведомления (бета): `TMS_SMTP_HOST/PORT/`
`USER/PASSWORD/FROM/STARTTLS`, `TMS_TG_BOT_TOKEN`.

### 2. Веб-клиент
```bash
cd web && npm install && npm run dev     # http://localhost:5173
```
`VITE_API_BASE` — адрес сервера (по умолчанию http://localhost:8000).

Интерфейс (SPA, мобильный клиент, сообщения QA, письма/Telegram-уведомления,
DOCX-котировки и счета) — на русском; в `<html lang="ru">` и подписях статусов
используется единый словарь (`web/src/api/labels.ts`, `mobile/src/labels.ts`).

### 3. Android
Готовый APK собирается в GitHub Actions (workflow `android-apk`) и при пуще
тега `v*` публикуется на странице Releases (`Mini-TMS-CAT_<версия>_android.apk`,
debug-подпись — ставится на любое устройство); локальная сборка —
`mobile/android/app/build/outputs/apk/debug/app-debug.apk`.
На экране входа вводится адрес сервера (`10.0.2.2` для эмулятора, IP компьютера
для телефона в той же Wi-Fi сети). Токены хранятся в SecureStore (§11).

Пересборка: `cd mobile && npx expo prebuild -p android --no-install`, затем
`cd android && JAVA_HOME=C:/Users/dolme/tools/jdk-17.0.20.1+1 ./gradlew.bat assembleDebug`.
Нюансы сборки (зеркало Maven, sdk.dir, версии) — в конце файла и в git-истории.

### 4. VPS через Docker (Portainer и без)
Один контейнер: FastAPI раздает и API, и собранный SPA; SQLite и загруженные
документы живут в томе `mini-tms-data` (/data).

```bash
git clone https://github.com/Dolmetscher/mini-tms.git && cd mini-tms
cp .env.example .env                      # впишите TMS_SECRET_KEY (длинная случайная строка)
docker compose up -d --build              # http://<сервер>:8080
```

В Portainer (без консоли): **Stacks → Add stack** → вставить `docker-compose.yml`
из репозитория → в Environment добавить `TMS_SECRET_KEY=…` → **Deploy the stack**.
Обновление — **Re-pull / Redeploy** (данные в томе переживают пересоздание).

Бэкап — одним файлом:
`docker run --rm -v mini-tms-data:/data -v $PWD:/backup alpine cp /data/tms.db /backup/`.
HTTPS — реверс-прокси перед контейнером (Caddy в двух строках конфига или
Nginx Proxy Manager из Portainer; не забудьте проксировать WebSocket `/ws`).

### 5. Обратная связь из интерфейса (бета)
Плавающая кнопка «💬 Feedback» есть на каждой странице: участник выбирает тип
(баг / идея / вопрос / другое), пишет текст — сообщение сохраняется вместе с
адресом страницы, где нажали кнопку. Лента — в UI менеджмента: страница
**Feedback** (фильтр по типу, ссылка на страницу отправителя); API — `GET /api/feedback`.
Анти-спам — не более `TMS_FEEDBACK_MAX_PER_HOUR` (10) сообщений в час от
пользователя.
Плюс автосбор JS-ошибок (мини-«Sentry» на том же эндпоинте): необработанные
исключения и unhandledrejection уходят баг-репортами с пометкой `[auto]` —
стек, страница, браузер; дедуп по «сообщение + файл:строка», капа на сессию,
при сбое самой отправки репортер замолкает (`web/src/crashReport.ts`).

### 6. Сборки и CI (GitHub Actions)
Три воркфлоу в `.github/workflows/`; репозиторий публичный — раннеры бесплатны:

- **docker** — образ «всё-в-одном» (FastAPI + собранный SPA) в GitHub Container
  Registry: каждый пуш в `main` → тег `latest`, тег `v*` → семвер-тег образа:
  ```bash
  docker pull ghcr.io/dolmetscher/mini-tms:latest   # или :0.2.0 для фиксации версии
  docker run -d -p 8080:8000 -v mini-tms-data:/data -e TMS_SECRET_KEY=… ghcr.io/dolmetscher/mini-tms:latest
  ```
  Пулл анонимный (образ публичный), Portainer/ compose-стек — как в разделе 4,
  но вместо `build:` просто `image: ghcr.io/dolmetscher/mini-tms:latest`.
- **desktop-builds** — Windows `.msi`/`-setup.exe`, macOS universal `.dmg`,
  Linux `.AppImage`/`.deb`; артефакты в прогоне, при теге — в Releases.
- **android-apk** — APK (debug-подпись); артефакт прогона и Releases.

Обновить все сборки разом: `git tag v0.2.x && git push origin main --tags`.
Ручной запуск без тега — вкладка Actions → нужный workflow → Run workflow
(бандлы тогда только в артефактах прогона, без Releases).

## Матрица соответствия ТЗ

| Требование | Реализация |
|---|---|
| FR-01 мультиаккаунт | мобильный: список аккаунтов (SecureStore), переключение без пароля (/me), выбор организации при входе, локальные данные с префиксом аккаунта; удаление аккаунта стирает локальные данные. Уведомление открывает задание в активном аккаунте; просроченная сессия → экран входа |
| FR-02 список заданий | проект+файл, языковая пара, дедлайн в локальной tz, статус, прогресс, сегменты/слова; поиск, фильтры по статусу, сортировка по дедлайну; принять/отклонить с причиной |
| FR-03 редактор | исходник/перевод, next/prev, «Confirm & Next» (следующий неподтвержденный, Ctrl+Enter), навигация Alt+↑/↓, поиск по тексту, фильтры (все/непереведенные/неподтвержденные/QA), контекст соседних сегментов, undo/redo, найти и заменить по всем сегментам (Ctrl+H), индикатор «Saved/Saving/No connection/Error»; правка подтвержденного снимает подтверждение; история правок сегмента (track changes, см. ниже) |
| FR-04 сохранность | черновик каждого сегмента локально мгновенно, очередь несинхронизированных правок, авто-повтор после восстановления связи, восстановление после перезапуска; конфликт 409 → диалог «Keep server / Overwrite with mine»; сдача только через сервер |
| FR-05 теги | профиль `<x/>`/`<g></g>`; отображение и вставка из исходника; QA `tag_error` (блокирует сдачу); структура сохраняется при экспорте (см. docs/formats.md) |
| FR-06 TM | авто-поиск при выборе сегмента: %, исходник, перевод, имя TM, тип (exact/fuzzy); вставка; конкордансный поиск по слову/фразе (mode=concordance: «как это переводилось раньше») и по целевому языку (side=target); 100% не подставляется и не подтверждается автоматически; подтвержденные переводы пишутся в TM с use_for_write (право задается при подключении ресурса); пред-перевод batch (exact или exact+fuzzy) и автопропагация повторов при подтверждении — черновиками, вычитка обязательна |
| FR-07 TB | термины исходника с переводом, примечанием и статусом (preferred/admitted/forbidden), вставка, ручной поиск, подсветка найденных терминов в исходнике активного сегмента (tooltip с переводом); несоблюдение терминологии — предупреждение QA |
| FR-03a комментарии | диалог переводчик ↔ менеджер в контексте сегмента: список + добавление, бейдж 💬 в списке сегментов, WS-обновление в реальном времени |

## Функции сверх ТЗ (второй проход развития)

Практики зрелых CAT/TMS (Trados/memoQ/XTRF), добавленные поверх обязательных требований:

- **XLIFF 2.0** (помимо обязательного 1.2): версия распознается автоматически,
  экспорт — в версии исходника; сегменты `<segment>` внутри `<unit>`,
  `<ignorable>` не переводится; inline-разметка 2.0 (`ph`/`pc`/изолированные
  пары `sc`+`ec`) нормализуется в единый профиль тегов редактора и при экспорте
  восстанавливается с атрибутами и native-кодом из исходника — совместимость
  с Phrase, Trados 2021+, memoQ (docs/formats.md).
- **Существующие переводы в XLIFF** (обе версии): файл из другого CAT-инструмента
  часто уже несет `<target>` — по `state` сегмента (2.0) / `approved` или
  `target@state` (1.2) они импортируются черновиками с ревизией «импортировано
  из файла»; подтверждение и QA остаются на переводчике. При экспорте `state`
  проставляется (`translated`; более высокие статусы не понижаются).
- **CSV-обмен TM** (паритет с глоссариями): импорт и экспорт с заголовком
  `source,target`, семантика upsert — как у TMX; round-trip без потерь
  (запятые, кавычки, переводы строк); в вебе — кнопки Import/Export CSV.
- **Отзыв токенов при смене пароля**: версия пароля в JWT (`pwd_ver`) — смена
  пароля инкрементирует её, и все ранее выданные токены (REST + WebSocket)
  перестают действовать; клиенту возвращается свежий токен, сессия
  продолжается без повторного входа. Мини-миграция колонки для существующих БД.
- **Пагинация больших ресурсов**: записи TM/TB листаются постранично
  (`limit`/`offset`, `X-Total-Count`), в вебе — «Load more»; записи за пределами
  первой страницы больше не недоступны менеджеру.
- **Биллинг**: прайс-листы организаций (ставка за слово по категориям анализа,
  валюта, минимальная сумма заказа) → котировки заданий и проектов из анализа
  объема (слова категории × ставка, практика Trados), экспорт котировки в DOCX
  для заказчика; в вебе — страницы Rates и блок Quote в дашборде проекта.
- **Доставка и закрытие цикла**: пакет доставки проекта — все сданные целевые
  файлы одним ZIP с манифестом (`GET /api/projects/{id}/deliver`, практика
  delivery package в XTRF/Plunet), и инвойс (закрывающий документ) в DOCX —
  та же математика, что в котировке, но только по заданиям в
  submitted/completed, с детерминированным номером `INV-<проект>-<дата>`;
  в вебе — карточка Delivery в дашборде проекта.
- **История правок сегмента (track changes)**: каждое изменение перевода
  фиксируется (автор/время/текст), включая пред-перевод и автопропагацию;
  в редакторе — панель History с восстановлением старой версии в черновик.
- **Отчет продуктивности переводчиков**: подтвержденные слова, принятые/
  просроченные задания, средняя LQA-оценка — данные для распределения заданий
  (страница Reports, фильтр по периоду).
- **Ведение ресурсов (maintenance)**: правка перевода и удаление записей TM
  (исходник — ключ памяти, не меняется), правка/удаление терминов TB со
  защитой от дублей — устаревший ресурс не работает против качества;
  в вебе — кнопки Edit/Delete в таблицах записей на странице TM/TB.
- **Гигиена аккаунта**: смена пароля с подтверждением текущего
  (`POST /api/change-password`, PBKDF2 200k) с отзывом всех ранее выданных
  токенов (версия пароля в JWT, проверяется и на WebSocket) и свежим токеном в
  ответе; защита логина от подбора — скользящее окно неудачных попыток на пару
  (логин, IP) с 429 и Retry-After; в вебе — кнопка Password в шапке.
- **Резервная копия организации**: полный JSON-дамп (проекты, задания, сегменты,
  TM/TB, прайс-листы, LQA, комментарии) одной кнопкой — аварийное восстановление
  и переносимость данных; хеши паролей не выгружаются.
- **SPA одним URL из коробки**: раздаваемый бэкендом веб-клиент обращается к API
  того же происхождения без ручного ввода адреса (vite dev по-прежнему на 5173).
- **Сегментные локи «кто редактирует — тот блокирует»** (практика облачных
  редакторов Phrase/Trados): открыв сегмент, редактор держит мягкий лок с TTL
  (10 мин, env `TMS_SEGMENT_LOCK_TTL`) и продлевает его heartbeat-ом; остальные
  видят занятость заранее — бейдж 🔒 с именем владельца в списке сегментов и
  read-only панель вместо текстового поля, а сервер на всякий случай отвечает
  423 на чужое сохранение. Вкладка, умершая без явного снятия, освобождает
  сегмент через TTL; менеджмент может снять чужой лок принудительно; сдача,
  возврат на доработку, отмена и переназначение задания снимают локи.
  Живые события — WS `segment_locked`/`segment_unlocked`.
- **RX-проверки QA** (практика verification settings в Trados/memoQ): организация
  описывает корпоративные требования правилами на регулярных выражениях —
  паттерн «не должен / должен встречаться» в исходнике или переводе, серьёзность
  warning (предупреждение) или error (блокирует сдачу), регистр учитывается
  опционально. Типовые правила: запрет заглушек `TODO`, двойных пробелов,
  латиницы в кириллическом переводе; обязательные типографские кавычки `«.+»`.
  Паттерн валидируется при создании (невалидный — 422), в вебе — вкладка
  QA Rules с созданием, вкл/выкл, удалением и предпросмотром «Test pattern»
  (прогон по образцу текста); нарушение попадает в QA-отчет с кодом
  `regex_rule` и переходом к сегменту.
- **Хоткеи редактора** (стандарт CAT): `Ctrl+Enter` — подтвердить и вниз,
  `Ctrl/Alt+↑↓` — навигация по сегментам, `Alt+T` — копировать исходник в
  перевод, `Ctrl+S` — сохранить черновик немедленно; работают при фокусе в
  любом месте страницы (кроме чужих полей ввода), не только в поле перевода.
- **Псевдо-перевод (pseudolocalization)**: сегменты заполняются синтетикой —
  диакритика + удлиннение ~40% + маркерные скобки, теги/числа/плейсхолдеры
  сохраняются; экспорт и QA на таком тексте проверяют всю цепочку (теги,
  числа, верстку длинных строк) до старта перевода. По умолчанию заполняются
  только пустые сегменты (консервативно, как пред-перевод), режим Overwrite —
  полный прогон; кнопка Pseudo-fill… в редакторе.
- **XLIFF-хендофф для внешних переводчиков**: экспорт задания в XLIFF 1.2
  (id = позиция сегмента; inline-теги становятся родными x/bpt/ept), файл
  открывается в Trados/memoQ/OmegaT; возврат мержится в то же задание: target
  с state translated/signed-off/final (или approved) подтверждается как
  ручной Confirm (запись в TM use_for_write + автопропагация повторов), прочие
  — черновики; сопоставление по id, фолбэк — по тексту исходника; чужие
  свежие локи сегментов уважаются (skip); история правок фиксирует импорт.
  Веб-редактор: кнопки «XLIFF handoff» / «Import XLIFF».
- **Выравнивание параллельных файлов → TM** (alignment, практика Trados
  Align Documents / memoQ): пара «старый исходник + старый перевод» (txt —
  строки, docx — абзацы) выравнивается по якорям — числам и именам собственным
  (лексика разных языков не совпадает, а якоря переживают перевод);
  difflib-блоки отображаются в индексы единиц, скор пары = совпавшие якоря /
  max(якорей). Предложение не пишет в TM: человек подтверждает пары галочками
  (в вебе — модалка Align files… на странице TM), запись — upsert, как у
  импорта. Пропущенный в переводе абзац не склеивается с соседним; совсем без
  якорей и при равном числе единиц — слабая позиционная гипотеза (score 0).
- **Внешние уведомления (бета)**: «действенные» события (назначение, сдача,
  возврат, отмена, просрочка) дублируются по email (SMTP, STARTTLS) и/или
  Telegram-боту; каналы включает администратор env-переменными, контакты
  пользователи задают себе сами (PATCH /api/me, форма на странице уведомлений;
  chat_id — у @userinfobot после /start боту). Доставка best-effort в фоновом
  потоке: сбой внешнего сервиса не ломает работу с заданиями.

## Осознанные ограничения MVP (отклонения/отложено)

- **Мобильный редактор не захватывает сегментные локи** (веб — захватывает):
  сохранение в чужой занятый сегмент вернет 423, что мобильный покажет как
  обычную ошибку сохранения; индикаторы занятости с владельцем — в вебе.

- **Push (FCM/APNs)** не подключен: требуется Google-проект и ключи; реализован
  центр уведомлений + WS-доставка (ТЗ прямо разрешает: push не единственный
  канал) и интерфейс-заглушка в `services/notify.py`.
- **Счетчик неудачных логинов** — в памяти процесса (скользящее окно 15 мин):
  перезапуск сбрасывает, для нескольких инстансов нужен внешний сторедж
  (Redis).
- **Локальные напоминания** на мобильном — через центр уведомлений при открытии
  приложения (без фоновых push).
- **Шифрование локального кэша** документов — отложено; токены в SecureStore,
  черновики в AsyncStorage приложения.
- **VoiceOver/TalkBack** — базовые accessibility-метки на ключевых элементах;
  глубокий аудит отложен.
- Подсчет слов и сегментация — правила MVP (docs/formats.md), требуют
  утверждения (§14 ТЗ).
- MT-провайдер LibreTranslate — публичный сервис может быть недоступен;
  редактор не блокируется.
