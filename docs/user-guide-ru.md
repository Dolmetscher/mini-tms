# Mini-TMS CAT — Руководство пользователя

Версия 0.2.0 · 11 ноября 2026 · [Dolmetscher/mini-tms](https://github.com/Dolmetscher/mini-tms)

# 1. О системе Mini-TMS
Mini-TMS — компактная CAT/TMS-система для управления переводческими проектами: CAT (Computer-Assisted Translation) означает, что переводчик работает в редакторе с памятью переводов, терминологией и машинным переводом, а TMS (Translation Management System) — что вокруг перевода выстроен полный управленческий цикл: проекты, задания, статусы, контроль качества, уведомления, котировки и приемка. Система рассчитана на малые команды и индивидуальных менеджеров переводческих процессов.

Основные возможности: организации с полной изоляцией данных; проекты и задания с жизненным циклом от назначения до приемки; память переводов (TM) с точным и нечетким поиском, конкордансом и автопропагацией повторов; терминологические базы (TB) со статусами терминов; машинный перевод (MT) по желанию; контроль качества (QA) со стандартными и регулярными проверками; пред-перевод и анализ объема; двуязычная выгрузка для ревью; LQA-оценка качества; уведомления по e-mail и Telegram; биллинг с котировками и инвойсами.

## 1.1. Клиенты
Система доступна из трех клиентов, работающих с одним сервером: веб-интерфейс (браузер, полная функциональность для менеджера и переводчика), десктопное приложение Mini-TMS CAT для Windows, macOS и Linux и мобильное приложение для Android (задания и перевод «на ходу»). Десктоп и мобильное приложение используют тот же вход по логину и паролю; адрес сервера вводится один раз на экране входа.

## 1.2. Интерфейс
Интерфейс веб-клиента, мобильного клиента, сообщения контроля качества, письма и Telegram-уведомления, а также документы котировок и счетов — полностью на русском языке. Веб-версия раздается сервером по одному адресу: откройте http://\<адрес-сервера\>:8000 (или порт, выбранный при установке), и вы получите и интерфейс, и API.Swagger-документация API доступна по адресу /docs.

> Дальше по тексту «pm» означает менеджера проектов (project manager), «администратор» — владельца организации, «переводчик» — исполнителя задания. Управляющие кнопки интерфейса приведены в кавычках так, как они называются на экране.

# 2. Быстрый старт (15 минут)
## 2.1. Запуск сервера (Docker)
Самый быстрый путь — Docker: сервер собирается и стартует четырьмя командами. Контейнер содержит и FastAPI-бэкенд, и собранный веб-интерфейс; база SQLite и загруженные файлы живут в томе mini-tms-data и переживают пересоздание контейнера.

> git clone https://github.com/Dolmetscher/mini-tms.git && cd mini-tms
>
> cp .env.example .env \# впишите TMS_SECRET_KEY — длинную случайную строку
>
> docker compose up -d --build

Через минуту-две сервис готов: откройте http://\<адрес-сервера\>:8080. В Portainer то же самое делается без консоли: Stacks → Add stack → вставить docker-compose.yml → в Environment добавить TMS_SECRET_KEY → Deploy the stack. Подробности установки, HTTPS и бэкапов — в главе 8.

## 2.2. Первый вход и смена пароля
При первом запуске сервер создает базу и демонстрационные данные: организацию Demo Org с пользователями admin/admin123 (администратор), pm/pm123 (менеджер), ann/ann123 и ivan/ivan123 (переводчики); память переводов «Demo TM» (en→ru), базу терминов «Demo TB», прайс-лист «Standard EN→RU» и проект Marketing Brochure с документом и заданием, назначенным переводчику ann.

Войдите как admin/admin123, выберите организацию Demo Org — и сразу смените пароль кнопкой «Password» в шапке: смена пароля немедленно отзывает все ранее выданные токены, включая чужие сессии с этим логином. Затем смените пароли остальных демо-пользователей, если оставляете их для знакомства.

## 2.3. Первый перевод (на демо-проекте)
Задание уже назначено, поэтому достаточно войти переводчиком ann/ann123 — и потренироваться на реальном цикле:

1.  Войдите как ann/ann123, выберите Demo Org.

2.  Откройте список заданий: Jobs → задание проекта Marketing Brochure (статус «назначено»).

3.  Нажмите «Accept» — задание перейдет в «принято», и откроется редактор.

4.  В редакторе переводите сегменты верхнюю-вниз: подсказки TM и термины подставляются автоматически при выборе сегмента.

5.  Переведенный сегмент подтверждайте Ctrl+Enter — подтверждение записывает перевод в TM и автоматически подставляет его в повторы.

6.  Кнопкой «Get MT» при необходимости запросите машинный перевод и, если он пригоден, вставьте в поле перевода.

7.  Когда все сегменты переведены и подтверждены, откройте QA (вкладка/кнопка качества): список замечаний с переходом к проблемному сегменту.

8.  Исправьте блокирующие замечания (обычно это непереведенные или неподтвержденные сегменты и ошибки тегов).

9.  Нажмите «Сдать задание» (Submit): задание уйдет в статус «сдано», менеджер получит уведомление.

10. Войдите теперь pm/pm123 — на дашборде проекта скачайте перевод (Export) или двуязычный DOCX для ревью, затем «Complete» для завершения.

Это весь цикл. Ниже каждая фаза разобрана подробно — от подготовки ресурсов до приемки и invoicing.

# 4. Полный цикл работы над проектом
Глава описывает «взрослый» сценарий: подготовить ресурсы, создать проект, проанализировать и назначить, довести перевод до сдачи, проверить, принять и выдать результат заказчику. Порядок подразделов совпадает с реальной последовательностью действий.

## 4.1. Ресурсы: память переводов (TM) и терминология (TB)
Память переводов хранит пары «исходник → перевод» и подсказывает их в редакторе; терминологическая база — глоссарий с обязательными и запрещенными терминами. Ресурсы создаются на уровне организации (раздел TM / TB), и к проекту подключаются нужные — с проверкой совместимости языков.

- Импорт TM: форматы TMX и CSV (заголовок source,target; семантика upsert — существующие пары обновляются, новые добавляются). Экспорт — TMX 1.4b и CSV, кругооборот без потерь.

- Импорт TB: TBX и CSV (term,translation,note,status). Экспорт — CSV и TBX-Basic. У термина есть статус: preferred (предпочтителен), admitted (допустим), forbidden (запрещен).

- При подключении TM к проекту задаются флаги search (искать совпадения) и write (записывать подтвержденные переводы). Право записи — осознанное решение: корпоративная память пополняется только качеством.

- Записи листаются постранично с кнопкой «Load more», поиск — по обеим сторонам пары. Устаревшие записи можно поправить (перевод) или удалить — исходник в TM не меняется, он ключ памяти.

Отдельная кнопка «Align files…» на странице TM запускает выравнивание: пара «старый исходник + старый перевод» (txt или docx) сопоставляется по якорям — числам и именам собственным — и предлагает кандидатов пар. Человек подтверждает пары галочками, и они попадают в TM (upsert). Так старые переводы, сделанные до внедрения системы, превращаются в рабочую память.

## 4.2. Машинный перевод (MT)
MT — это подсказка, а не замена переводчика: кнопка «Get MT» в редакторе запрашивает перевод текущего сегмента, результат помечается провайдером и вставляется только явным действием пользователя — введенный текст не перетирается. Провайдеры: LibreTranslate (адрес и ключ задаются переменными TMS_MT_URL и TMS_MT_API_KEY) и mock для тестов; по умолчанию MT отключен. Организация может запретить MT политикой org.mt_allowed, проект — флагом MT в настройках. Если внешняя служба недоступна, редактор продолжает работать — просто без подсказки.

## 4.3. Создание проекта и загрузка файлов
Проект создает pm или администратор: языковая пара (на каждый целевой язык создается отдельное задание), дедлайн, инструкции для переводчиков, файлы. Поддерживаемые исходные форматы: TXT, XLIFF 1.2, XLIFF 2.0, DOCX; версия XLIFF определяется автоматически, и экспорт вернется в версии исходника. К проекту подключаются TM и TB с нужными флагами, MT включается или выключается. Загруженные документы обрабатываются асинхронно: большой файл не блокирует интерфейс, статус обработки виден в карточке документа.

Если в XLIFF уже есть переводы (файл из другого CAT-инструмента), они импортируются черновиками — по state сегмента; подтверждение остается за переводчиком. Inline-разметка (теги) сохраняется и при импорте, и при экспорте: пары ph/pc, sc/ec в 2.0 и bpt/ept/x в 1.2 нормализуются в единый профиль тегов редактора и восстанавливаются при выгрузке.

## 4.4. Анализ объема и пред-перевод
До старта перевода выполните анализ (Analysis в карточке задания): каждая категория — exact (точные совпадения с TM), fuzzy-банды (нечеткие совп. по процентам), повторы и новые сегменты — считает слова; взвешенная сумма (веса настраиваются переменными TMS_ANALYSIS\_\*) и есть объем работ. Котировка строится из анализа по прайс-листу — см. главу 6.

Pre-translate подставит из TM точные совпадения (режим exact) или точные плюс нечеткие (exact+fuzzy) и распространит переводы на повторы. Все подстановки — черновики без подтверждения: вычитка обязательна. Тот же принцип у автопропагации: подтверждаете сегмент — идентичные сегменты получают черновик с тем же переводом.

Для проверки всей цепочки до старта перевода полезен псевдо-перевод (Pseudo-fill в редакторе): сегменты заполняются синтетикой (диакритика, удлинение ~40%, маркерные скобки), теги, числа и плейсхолдеры сохраняются. Экспорт и QA на таком тексте проверяют пайплайн — теги, числа, верстку длинных строк — не переводя ни слова. По умолчанию заполняются только пустые сегменты; режим Overwrite прогоняет и непустые.

## 4.5. Назначение задания и жизненный цикл
Задание назначается конкретному участнику с индивидуальным дедлайном; переводчик принимает его (Accept) или отклоняет с причиной (Decline). Повторное назначение сохраняет уже сделанный перевод. Жизненный цикл — конечный автомат на сервере: недопустимые переходы отклоняются.

**Таблица 2. Статусы задания**

| **Статус**  | **Что означает**                    | **Что дальше**                        |
|-------------|-------------------------------------|---------------------------------------|
| unassigned  | Создано, исполнитель не выбран      | pm: Assign                            |
| assigned    | Назначено, ждет реакции исполнителя | переводчик: Accept или Decline        |
| accepted    | Принято к работе                    | первое редактирование → in_progress   |
| in_progress | Ведется перевод                     | переводчик: Submit                    |
| submitted   | Сдано, на проверке у pm             | pm: Complete или Return               |
| rework      | Возвращено с комментарием           | переводчик дорабатывает, снова Submit |
| completed   | Принято, цикл закрыт                | экспорт и доставка (гл. 4.10)         |
| canceled    | Отменено, редактирование закрыто    | —                                     |

Просрочка — не статус, а вычисляемый признак: дедлайн прошел, а задание не сдано. Прогресс считается по подтвержденным обязательным сегментам от всех обязательных и показан в списке заданий и на дашборде; 100% прогресса не заменяет действия «Сдать задание». Напоминания о дедлайне приходят автоматически за 24 часа и за 2 часа.

## 4.6. Работа в редакторе
Редактор — центральное рабочее место переводчика. Слева список сегментов с исходником и переводом, бейджами статусов, комментариев 💬 и занятости 🔒; справа — панель контекста: подсказки TM, термины, MT, история правок и комментарии. Выбор сегмента автоматически ищет совпадения в подключенных TM: точное показывает 100%, нечеткое — процент, исходник, перевод и имя памяти; вставка — одним кликом. Термины TB находятся в исходнике активного сегмента, подсвечиваются прямо в тексте, а подсказка с переводом всплывает по термину; конкордансный поиск («как это переводилось раньше») ищет по слову или фразе в обеих сторонах памяти.

**Таблица 3. Горячие клавиши редактора**

| **Клавиши**    | **Действие**                                                 |
|----------------|--------------------------------------------------------------|
| Ctrl+Enter     | Подтвердить сегмент и перейти к следующему неподтвержденному |
| Ctrl/Alt + ↑ ↓ | Навигация по сегментам (следующий/предыдущий)                |
| Alt+T          | Скопировать исходник в поле перевода                         |
| Ctrl+S         | Сохранить черновик немедленно                                |
| Ctrl+H         | Найти и заменить по всем сегментам задания                   |

Хоткеи работают при фокусе в любом месте страницы, а не только в поле перевода. Фильтры списка сегментов: все, непереведенные, неподтвержденные, QA-проблемы. Правка подтвержденного сегмента автоматически снимает подтверждение — статус не «залипает». Индикатор сохранения в шапке редактора показывает «Saved» / «Saving» / «No connection» / «Error»; конфликт версий (кто-то сохранил сегмент раньше, 409) предлагается решить диалогом «Keep server» (взять серверную версию) или «Overwrite with mine» (перезаписать своей).

Занятость сегментов: открыв сегмент, редактор держит мягкий лок с TTL 10 минут и продлевает его активностью; остальные участники видят бейдж 🔒 с именем владельца и поле только для чтения, а сервер на всякий случай отвечает 423 на чужое сохранение. Умершая вкладка освободит сегмент через TTL, менеджмент может снять лок принудительно. Комментарии к сегменту — диалог переводчик ↔ менеджер в контексте строки: новый комментарий виден обоим мгновенно. История правок (панель History) хранит каждую версию перевода с автором и временем, включая пред-перевод и автопропагацию; старую версию можно вернуть в черновик.

## 4.7. Контроль качества (QA)
QA прогоняется по кнопке качества в задании: список замечаний с кодом, текстом и переходом к сегменту; сдача возможна только при нулевом количестве блокирующих. Предупреждения не блокируют, но их стоит вычитать — это стандартные практики CAT.

**Таблица 4. Проверки QA**

| **Проверка**                                  | **Серьёзность** |
|-----------------------------------------------|-----------------|
| Отсутствует перевод в обязательном сегменте   | Блокирует сдачу |
| Неподтвержденные обязательные сегменты        | Блокирует сдачу |
| Нарушение структуры тегов                     | Блокирует сдачу |
| Числа не совпадают с исходником               | Предупреждение  |
| Несоблюдение терминологии; запрещенный термин | Предупреждение  |
| Двойные и краевые пробелы                     | Предупреждение  |
| Повтор слова в переводе                       | Предупреждение  |
| Дисбаланс скобок и кавычек                    | Предупреждение  |
| Конечная пунктуация отличается                | Предупреждение  |
| Совпадение с исходником при разных языках     | Предупреждение  |
| Плейсхолдеры (%s, %d, %1\$s, {0}, Qt %1)      | Предупреждение  |
| Аномальное соотношение длины перевод/исходник | Предупреждение  |

Поверх стандартных — RX-правила организации (вкладка QA Rules): регулярное выражение «не должен / должен встречаться» в исходнике или переводе, серьёзность warning или error (error блокирует сдачу), регистр — опционально. Паттерн проверяется при создании (невалидный не сохранится), а перед сохранением его можно прогнать по образцу текста кнопкой «Test pattern». Типовые правила: запрет заглушек TODO, двойных пробелов, латиницы в кириллическом переводе; обязательность типографских кавычек «.+». Нарушение правила попадает в QA-отчет с кодом regex_rule и переходом к сегменту.

## 4.8. Обмен с внешними CAT-инструментами (XLIFF-хендофф)
Если исполнитель привык работать в Trados, memoQ или OmegaT — задание выгружается кнопкой «XLIFF handoff»: XLIFF 1.2 с исходником, текущим переводом и state; inline-теги становятся родными для внешнего инструмента. Готовый файл возвращается кнопкой «Import XLIFF»: сегменты сопоставляются по id (фолбэк — по тексту исходника), строки с state translated, signed-off, final или approved подтверждаются как ручной Confirm — с записью в TM и автопропагацией, — прочие становятся черновиками. Чужие свежие локи сегментов уважаются (такие строки пропускаются), история правок фиксирует импорт.

## 4.9. Ревью и LQA-оценка качества
Для вычитки на сторону выгружается двуязычный DOCX (№ / исходник / перевод) — comfortable формат для корректора или заказчика. Оценка качества — LQA в духе MQM: pm размечает ошибки по категориям (accuracy — точность, terminology — терминология, fluency — плавность, style — стиль, locale — локальные нормы, consistency — согласованность) и серьёзности: minor 1 балл, major 5, critical 10. Итог: score = 100 − штраф×1000/слов с порогом зачета (по умолчанию 95, настраивается). Оценка и число ошибок прикладываются к возврату задания — переводчик видит, за что его вернули.

## 4.10. Приемка, выгрузка и доставка
Приняв задание (Complete), pm закрывает цикл: сданный перевод скачивается экспортом в формате исходника (структура документа и теги сохранены, проставляется state переведенных сегментов). Дальше работают агрегированные инструменты: пакет доставки проекта — все сданные целевые файлы одним ZIP с манифестом (кнопка Delivery на дашборде проекта) и инвойс DOCX с детерминированным номером INV-\<проект\>-\<дата\> — закрывающий документ для заказчика; математика та же, что в котировке, но только по заданиям в submitted/completed.

# 5. Уведомления, комментарии и обратная связь
## 5.1. Центр уведомлений и события в реальном времени
Все ключевые события — назначение, принятие, сдача, возврат, завершение, отмена, просрочка, комментарии к сегментам, LQA-ошибки — приходят в центр уведомлений и на WebSocket-канал: дашборды и списки обновляются без перезагрузки. Обязательные события ТЗ адресные; напоминания о дедлайне приходят за 24 часа и за 2 часа автоматически.

## 5.2. E-mail и Telegram (бета)
Действенные события дублируются во внешние каналы: e-mail через SMTP (STARTTLS) и/или Telegram-бот. Каналы включает администратор переменными TMS_SMTP\_\* и TMS_TG_BOT_TOKEN, а каждый пользователь сам задает себе контакты — e-mail и chat_id в форме на странице уведомлений (тот же PATCH /api/me). chat_id узнается у @userinfobot после /start вашему боту. Доставка — best-effort в фоне: сбой внешнего сервиса не мешает работе с заданиями.

## 5.3. Кнопка «Обратная связь» и автосбор ошибок
Плавающая кнопка «💬 Feedback» есть на каждой странице: участник выбирает тип (баг / идея / вопрос / другое), пишет текст — сообщение сохраняется вместе с адресом страницы, на которой кнопку нажали. Лента — в UI менеджмента: страница Feedback с фильтром по типу и ссылкой на страницу отправителя. Анти-спам: не более 10 сообщений в час от одного пользователя. Дополнительно браузер сам сообщает о необработанных JS-ошибках: репорты с пометкой \[auto\] несут стек, страницу и браузер; репортер дедуплицирует повторы и замолкает, если отправка сама по себе падает — цикл обратной связи не зацикливается.

# 6. Биллинг, котировки и отчеты
Прайс-лист организации (страница Rates) задает ставку за слово по категориям анализа — exact, fuzzy-банды, повторы, новые — валюту и минимальную сумму заказа; валюта новых прайс-листов по умолчанию — TMS_RATE_CURRENCY. Котировка (блок Quote в дашборде проекта и в карточке задания) умножает слова категорий на ставки: видны итоги по валютам и пары без прайс-листа (missing_pairs). Котировка экспортируется в DOCX — документ для заказчика с таблицей категорий, минимальной суммой и итогом.

Отчет продуктивности (страница Reports, фильтр по периоду) показывает по переводчикам: подтвержденные слова, задания, принятые и просроченные, среднюю LQA-оценку — данные для распределения будущих заданий. Аварийный инструмент — бэкап организации одной кнопкой: полный JSON-дамп (проекты, задания, сегменты, TM/TB, прайс-листы, LQA, комментарии; хеши паролей не выгружаются).

# 7. Клиенты: веб, десктоп, Android
## 7.1. Веб-браузер
Основной клиент. Сервер раздает интерфейс и API по одному адресу — просто откройте адрес сервера в браузере. Если интерфейс размещен отдельно от API, адрес сервера вводится на экране входа и хранится в localStorage: одна сборка работает с любым сервером. При локальной разработке веб-клиент стартует командой npm run dev на порту 5173, адрес API задается переменной VITE_API_BASE.

## 7.2. Десктоп (Windows, macOS, Linux)
Установщики публикуются на странице Releases репозитория GitHub: для Windows — NSIS-установщик и .msi (требуется WebView2, который уже есть в Windows 10/11), для macOS — универсальный dmg (Intel и Apple Silicon), для Linux — AppImage и deb. Десктоп — это тот же веб-интерфейс в нативной рамке: адрес сервера вводится на экране входа. При первом запуске на macOS (сборка без подписи): правый клик по приложению → Open.

## 7.3. Android
APK публикуется на странице Releases (debug-подпись — ставится на любое устройство). На экране входа укажите адрес сервера: для эмулятора это 10.0.2.2, для телефона в той же Wi-Fi-сети — IP компьютера. Токены хранятся в SecureStore. Мобильный клиент поддерживает мультиаккаунт: список аккаунтов с переключением без пароля, выбор организации при входе, локальные данные с префиксом аккаунта; уведомление открывает задание в активном аккаунте, истечение сессии возвращает на экран входа.

> Мобильный редактор не захватывает сегментные локи (веб — захватывает): сохранение в сегмент, занятый в вебе, вернет ошибку сохранения. Индикаторы занятости с именем владельца доступны в веб-клиенте.

# 8. Установка и администрирование
## 8.1. Установка на сервер (Docker)
Рецепт из быстрого старта подходит и для продакшена: клонировать репозиторий, задать TMS_SECRET_KEY, docker compose up -d --build; сервис слушает порт 8080 (проброс на 8000 контейнера). База SQLite и загруженные документы живут в томе mini-tms-data (/data) и переживают пересоздание контейнера. Для VPS с 1 ГБ памяти достаточно: контейнер с одним uvicorn-воркером укладывается примерно в сотню мегабайт.

## 8.2. Обновление
Обновление — Repull/Redeploy стека в Portainer или docker compose pull && docker compose up -d, если используется готовый образ реестра; данные в томе остаются. Событие обновления без даунтайма не гарантируется — планируйте окно вне активной работы.

## 8.3. Резервное копирование
Полный бэкап — одним файлом: docker run --rm -v mini-tms-data:/data -v \$PWD:/backup alpine cp /data/tms.db /backup/ — заберите файл tms.db. Логические бэкапы организаций (JSON) делаются кнопкой из интерфейса — гл. 6. Восстановление: остановите стек, верните tms.db в том, запустите стек.

## 8.4. HTTPS
HTTPS ставится реверс-прокси перед контейнером: Caddy в двух строках конфигурации или Nginx Proxy Manager из Portainer. Не забудьте проксировать WebSocket-канал /ws — без него живые обновления в интерфейсе не работают (остальное — работает).

## 8.6. Безопасность
Пароли хранятся хешем PBKDF2 (200k итераций), сессии — JWT. Смена пароля отзывом аннулирует все ранее выданные токены (и REST, и WebSocket), выдавая взамен свежий: сессия пользователя продолжается без повторного входа. Подбор логина ограничен скользящим окном неудачных попыток на пару «логин, IP» — 429 с Retry-After. Изоляция организаций проверяется на сервере в каждом запросе. Технические логи не содержат текстов документов; аудит фиксирует назначения, смены статусов, прав и ресурсов.

# 9. Частые вопросы и неполадки
**Вопрос. Кнопка «Submit» не нажимается / сдача не проходит.**

Проверьте QA-отчет: блокирующие замечания (нет перевода, неподтвержденные обязательные сегменты, теги, RX-правило с error) закрывают сдачу. Каждое замечание — переходом к сегменту.

**Вопрос. Сегмент стал серым и не редактируется, рядом 🔒.**

Сегмент редактирует другой участник: мягкий лок с TTL 10 минут. Дождитесь освобождения (владелец ушел — лок истечет сам) или попросите менеджера снять лок принудительно.

**Вопрос. Появилось окно «Keep server / Overwrite with mine».**

Конфликт версий (409): сегмент изменили после вашей загрузки. «Keep server» берет серверную версию, «Overwrite» записывает вашу — выбирайте осознанно, история правок сохранит обе.

**Вопрос. «Get MT» не отвечает.**

Внешний провайдер (LibreTranslate) недоступен или не настроен переменными TMS_MT_URL / TMS_MT_API_KEY. Редактор продолжает работать без MT; проверьте также, что MT разрешен политикой организации и флагом проекта.

**Вопрос. После смены пароля на другом устройстве выкинуло из системы.**

Так задумано: смена пароля отзывает все ранее выданные токены. Войдите заново с новым паролем.

**Вопрос. Пред-перевод заполнил сегменты, но прогресс не растет.**

Подстановки — черновики без подтверждения. Прогресс считается по подтвержденным обязательным сегментам: пройдитесь по сегментам и подтвердите их (Ctrl+Enter).

**Вопрос. Перевод из мобильного приложения не сохраняется на занятом сегменте.**

Мобильный клиент не захватывает локи, а сервер отвечает 423 на чужое сохранение — сохранение выглядит как обычная ошибка. Подождите освобождения сегмента или работайте в веб-клиенте.

**Вопрос. Где сданный файл?**

Экспорт — в карточке задания (формат исходника), двуязычный DOCX для ревью — там же. Все сданные файлы проекта одним ZIP — карточка Delivery на дашборде проекта.

**Вопрос. Как восстановить данные из бэкапа?**

Файловый бэкап: остановить стек, вернуть tms.db в том mini-tms-data, запустить стек. JSON-бэкап организации — для выборочного разбора и переноса данных (пароли в нем нет).

**Вопрос. Демо-данные остались — это нормально для продакшена?**

Нет: сразу после установки смените пароли демо-пользователей (admin, pm, ann, ivan), а демо-организацию удалите, когда создадите свою.

# 10. Глоссарий
**Таблица 6. Термины**

| **Термин**               | **Определение**                                                                                     |
|--------------------------|-----------------------------------------------------------------------------------------------------|
| CAT                      | Computer-Assisted Translation — перевод с инструментальной поддержкой: память, терминология, MT, QA |
| TMS                      | Translation Management System — управление проектами перевода: задания, статусы, биллинг, приемка   |
| Сегмент                  | Единица перевода (предложение или фраза), с которой работает редактор                               |
| TM                       | Translation Memory — память переводов: пары «исходник → перевод», накопленные ранее                 |
| TB                       | Term Base — терминологическая база (глоссарий) со статусами терминов                                |
| MT                       | Machine Translation — машинный перевод (в Mini-TMS — только подсказка)                              |
| Exact / Fuzzy            | Точное / нечеткое совпадение сегмента с TM (в процентах)                                            |
| Автопропагация           | Перенос подтвержденного перевода на идентичные сегменты задания                                     |
| Конкорданс               | Поиск по TM: «как это слово/фраза переводилось раньше»                                              |
| QA                       | Quality Assurance — автоматический контроль качества перевода                                       |
| LQA / MQM                | Linguistic Quality Assessment — ручная оценка качества по категориям ошибок                         |
| RX-правило               | Корпоративная проверка на регулярном выражении (must / must not match)                              |
| XLIFF                    | XML Localization Interchange File Format — двуязычный обменный формат (1.2/2.0)                     |
| TMX / TBX                | Открытые форматы обмена памятью переводов / терминологией                                           |
| Хендофф (handoff)        | Передача задания во внешний CAT-инструмент через XLIFF и возврат                                    |
| Выравнивание (alignment) | Сопоставление старых исходника и перевода для пополнения TM                                         |
| Лока (lock)              | Мягкая блокировка сегмента на время редактирования (TTL)                                            |
| Леверидж                 | Повторное использование накопленных переводов — основа экономики CAT                                |
