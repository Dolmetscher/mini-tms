# Профили поддержки документов (§9 ТЗ)

Ниже описаны поддерживаемые элементы и ограничения каждого формата. Все правила
проверяются тестами (`backend/tests/test_cat.py`).

## Общие правила

- **Сегментация**: документ разбивается на сегменты при импорте; для каждого
  целевого языка проекта создается отдельное задание (§4 ТЗ).
- **Теги**: поддерживается профиль inline-тегов `<x id="N"/>` (одиночный) и
  `<g id="N"> … </g>` (парный). Редактор отображает теги исходника как кнопки
  для вставки; QA-проверка `tag_error` (блокирующая) контролирует наличие всех
  тегов источника в переводе и корректность вложенности пар (FR-05).
- **Подсчет слов** (правила MVP, подлежат уточнению в §14 ТЗ): слова считаются
  регулярным выражением `[0-9A-Za-zА-Яа-яЁё]+([-'][0-9A-Za-zА-Яа-яЁё]+)*`
  по тексту без служебных тегов. Для языков без пробелов (китайский,
  японский, корейский) каждая идеограмма/слог считается отдельным словом —
  стандартная упрощенная практика подсчета объема CJK.
- **Неподдерживаемые элементы** не удаляются молча: они остаются в исходном
  файле, а при импорте фиксируются в `processing_notes` документа и показываются
  в интерфейсе.

## TXT (UTF-8)

- Импорт: каждая непустая строка — сегмент. Кодировка UTF-8 (fallback cp1252).
- Экспорт: сегменты перевода склеиваются `\n` в новый файл; исходное
  форматирование строк (ведущие пробелы) не сохраняется.
- Ограничения: нет inline-тегов и форматирования.

## DOCX (базовый профиль)

- Импорт (python-docx): непустые абзацы тела документа — сегменты, в порядке следования.
  Пустые абзацы пропускаются.
- **Не поддерживается** (фиксируется в notes): таблицы, картинки, колонтитулы,
  сноски; текст внутри них не переводится.
- Экспорт: текст абзаца заменяется переводом; **форматирование runs внутри
  абзаца упрощается** до первого run (жирный/курсив внутри абзаца теряются,
  стиль абзаца сохраняется). Это документированное упрощение профиля MVP.
- Ограничение тегов: DOCX-профиль не создает inline-тегов.

## XLIFF 1.2

- Импорт (lxml): каждый `<trans-unit>` с непустым `<source>` — сегмент, в
  порядке следования. Файлы с xmlns и без обрабатываются одинаково.
- **Существующие переводы** (импорт): `approved="yes"` на trans-unit или
  `state="translated"/"signed-off"/"final"` на `<target>` + непустой target →
  черновик без подтверждения (вычитка обязательна); порядок детей внутри
  trans-unit (target до/после source) не важен.
- Inline-элементы источника нормализуются в токены сегмента:
  - `<x id="N"/>` → `<x id="N"/>`
  - `<ph id="N">…</ph>` → `<x id="N"/>` (содержимое сохраняется в файле и
    восстанавливается при экспорте, в редакторе показывается как тег)
  - `<bpt id="N">…</bpt> … <ept id="N">…</ept>` → `<g id="N"> … </g>`
  - прочие inline-элементы (`it`, `sub`, `mrk`) проходят транзитом и помечаются note.
- Экспорт: токены перевода восстанавливаются в оригинальные inline-элементы —
  атрибуты и содержимое (payload) bpt/ept/ph клонируются из исходного файла по
  id; переводимый текст записывается между ними. Остальной XML файла
  (структура, header, описания) сохраняется без изменений. У файла добавляется
  или перезаписывается элемент `<target>` каждого trans-unit; на `<target>`
  проставляется `state="translated"` (`signed-off`/`final` не понижаются).
  Атрибут `approved` trans-unit не изменяется.
- Ограничения: вложенные `<g>` внутри `<g>` в источнике трактуются как
  независимые пары; сегменты с пустым source пропускаются.

## XLIFF 2.0

Версия определяется автоматически по атрибуту `version` корня — расширения
`.xlf`/`.xliff` принимаются для обеих версий, экспорт всегда в версии исходника.
Формат используется современными CAT (Phrase, Trados 2021+, memoQ), поэтому
обе версии — минимальный уровень совместимости.

- Импорт (lxml): каждый `<segment>` внутри `<unit>` с непустым `<source>` —
  сегмент. Namespace `urn:oasis:names:tc:xliff:document:2.0` (разбор
  namespace-агностичный). `<ignorable>` не переводится и сегментом не
  становится (это и есть смысл элемента по спецификации).
- **Существующие переводы** (импорт): `state="translated"/"reviewed"/"final"`
  + непустой `<target>` → перевод импортируется как черновик без
  подтверждения (вычитка обязательна — как пред-перевод из TM); `state="initial"`
  или пустой target → сегмент пустой. Ревизия сегмента фиксирует импорт
  (автор — загрузивший файл).
- Inline-разметка нормализуется в токены сегмента:
  - `<ph id="N">…</ph>` → `<x id="N"/>` (native-код не показывается в редакторе)
  - `<pc id="N">…</pc>` → `<g id="N"> … </g>` (текст внутри контейнера —
    переводится, это главное отличие от 1.2, где bpt/ept — отдельные соседи)
  - изолированная пара `<sc id="N"/> … <ec id="N"/>` (общий id) →
    `<g id="N"> … </g>`; непарные `sc`/`ec` остаются текстом с note
  - `<mrk>` (аннотации) обходится как текст с note
- Экспорт: `<pc>` создается заново с атрибутами оригинала (id, type, …),
  перевод — внутрь; `<ph>`/`<sc>`/`<ec>` клонируются из исходника по id
  (native-код и атрибуты сохраняются); `<target>` добавляется/перезаписывается
  внутри `<segment>`. Остальной XML сохраняется как был. **`state` сегмента**
  проставляется `translated` (по спецификации default `initial` означал бы
  «перевод не начат»); `reviewed`/`final` не понижаются.
- Ограничения: перекрывающиеся изолированные пары sc/ec (sc₁ sc₂ ec₁ ec₂)
  восстанавливаются в порядке следования токенов, а не исходного вложения —
  перевод при этом не теряется.

## Сдача и экспорт (FR-09/FR-14)

- Экспорт результата доступен менеджеру после сдачи (`submitted`) или
  завершения (`completed`) задания.
- Критические ошибки тегов (`tag_error`) блокируют сдачу; предупреждения
  (`number_mismatch`, `terminology`) — нет.

## Обмен ресурсами: TMX, TBX, CSV

- **TMX 1.4b** (экспорт/импорт TM): `<tu>` → `<tuv xml:lang>`; round-trip
  без потерь проверяется тестами.
- **TBX-Basic / LISA TBX 1.0** (экспорт/импорт TB): `martif → text → body →
  termEntry → langSet(xml:lang) → tig → term`. Статус термина —
  `<termNote type="normativeAuthorization">` (`preferredTerm` / `admittedTerm`
  / `forbiddenTerm`), примечание — `<descrip type="note">` на уровне
  termEntry. Импорт дополнительно принимает короткие статусы
  (`preferred`/…), примечание в `termNote type="note"` и языки с региональными
  суффиксами (`en` в TB матчит `en-US` в `xml:lang`). Round-trip без потерь
  проверяется тестами (`test_review.py`).
- **CSV** (TB): заголовок `term,translation,note,status`, UTF-8 с BOM для
  Excel; полный round-trip с импортом.
- **CSV** (TM): импорт и экспорт — заголовок `source,target` (регистр
  заголовка любой), UTF-8 с BOM для Excel; семантика — как у TMX: `source` —
  ключ памяти, совпадения обновляют перевод. Дубли source внутри одного файла
  обрабатываются корректно (последний выигрывает), строки без перевода
  skip-аются. Полный round-trip: экспорт импортируется обратно без потерь
  (запятые, кавычки и переводы строк переживают CSV-кавирование).
- **Поиск записей TM** — по обеим сторонам (исходник и перевод), как у TB;
  в вебе — то же поле «Search entries…».
- **Пагинация записей ресурсов**: `GET …/entries` принимает `limit` (≤500)
  и `offset`, общее число записей (с учетом поиска `q`) — в заголовке
  `X-Total-Count`; в вебе — кнопка «Load more».
