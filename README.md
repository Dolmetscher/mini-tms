# Mini-TMS — мобильная CAT-система (по ТЗ)

CAT (Computer-Assisted Translation) система: организации с изоляцией данных,
проекты и задания с полным жизненным циклом, память переводов (TM),
терминологические базы (TB), машинный перевод (MT), контроль качества,
пред-перевод и анализ объема (леверидж TM), двуязычная выгрузка для ревью,
уведомления и мультиаккаунтность. Реализовано по ТЗ (`ТЗ САТ.txt`); матрица
соответствия — ниже.

## Компоненты

```
┌────────────────────┐   ┌────────────────────┐
│ Web-клиент (React) │   │ Mobile (Expo RN →  │
│ PM + переводчик    │   │ APK для Android)   │
│ + Desktop (Tauri,  │   │                    │
│ win64/macOS)       │   │                    │
└─────────┬──────────┘   └─────────┬──────────┘
          │ REST (JWT + X-Org-Id)  │
          │ WebSocket /ws/updates  │
          ▼                        ▼
┌────────────────────────────────────────────┐
│ FastAPI: auth/orgs/projects/jobs/tm/tb/    │
│ notifications; сервисы QA, MT, тегов,      │
│ сегментации, экспорта, напоминаний, аудита │
└───────────────────┬────────────────────────┘
                    ▼
         SQLite (SQLAlchemy) + файлы документов в data/
```

- **Роли** (на уровне организации): `admin`, `pm`, `translator`; один пользователь
  может состоять в нескольких организациях с разными ролями. Доступ проверяется
  на сервере: заголовок `X-Org-Id` + membership; все выборки фильтруются по org_id.
- **Жизненный цикл задания** (§7 ТЗ): unassigned → assigned → accepted →
  in_progress → submitted → completed / rework → … → canceled. Просрочка —
  вычисляемый признак, не статус.
- **Прогресс** (формула ТЗ): подтвержденные обязательные сегменты / все
  обязательные × 100%. Прогресс 100% не заменяет действие «Сдать задание».

## Веб и десктоп

Система доступна в трех видах из одного кода веб-клиента:

1. **Веб-версия одним URL**: FastAPI раздает собранный SPA — запустите сервер
   и откройте `http://<сервер>:8000` (роуты `/api/*` и `/ws` имеют приоритет,
   остальные пути отдают `index.html`). Отдельный статик-хостинг не нужен;
   при желании `web/dist` можно выложить куда угодно и задать `VITE_API_BASE`.
   Адрес сервера также вводится на экране входа (хранится в localStorage) —
   это позволяет одной сборке работать с любым сервером.
2. **Windows x64**: готовые установщики —
   `desktop-builds/Mini-TMS-CAT_0.1.0_x64-setup.exe` (NSIS, 1.7 МБ) и
   `Mini-TMS-CAT_0.1.0_x64.msi`. Пересборка локально: `desktop\build.cmd`
   (см. нюансы тулчейна ниже). Требуется только WebView2 (есть в Windows 10/11).
3. **macOS (dmg, universal — Intel + Apple Silicon)**: собирается в GitHub
   Actions (`desktop-builds` workflow). Как запустить:
   ```bash
   cd mini-tms
   git remote add origin https://github.com/<user>/mini-tms.git
   git push -u origin main --tags        # либо без тега: вкладка Actions → desktop-builds → Run workflow
   ```
   Артефакты появятся во вкладке Actions. Сборка без подписи — при первом
   запуске macOS: правый клик по приложению → Open.

Локальная сборка Windows (Tauri 2 + GNU-тулчейн) требует полного MinGW:
на этой машине он собран в `C:\Users\dolme\tools\mingw-ucrt` из пакетов msys2
(binutils, gcc, gmp/mpfr/mpc/isl, zlib/zstd/gettext/libiconv, libgcc, libstdc++,
libwinpthread — зеркало TUNA). Линкер — self-contained gcc из rustup
(`CARGO_TARGET_X86_64_PC_WINDOWS_GNU_LINKER` в `desktop\build.cmd`), т.к. у
msys2-gcc нет CRT-импорт-либ (mingwex/kernel32). CI собирает через MSVC — там
эти шаги не нужны.

## Запуск

### 1. Сервер (Python 3.12+)
```bash
cd backend
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt      # Linux/macOS: .venv/bin/pip
.venv/Scripts/python -m uvicorn app.main:app --port 8000
.venv/Scripts/python -m pytest tests/ -q           # 41 тест: §12 + QA/TMX/конкорданс/CJK + леверидж + LQA/TBX/комментарии + биллинг/история/отчеты
```
Swagger: http://localhost:8000/docs. Первый запуск создает БД и демо-данные:
- организация **Demo Org**, пользователи `admin/admin123` (org admin),
  `pm/pm123`, переводчики `ann/ann123`, `ivan/ivan123`;
- TM «Demo TM» (en→ru), TB «Demo TB» (с preferred/forbidden терминами),
  прайс-лист «Standard EN→RU» (EUR, ставки по категориям, минимальная сумма 15);
- проект «Marketing Brochure» с документом и заданием, назначенным на ann.

Env-переменные: `TMS_SECRET_KEY`, `TMS_DATABASE_URL`, `TMS_DATA_DIR`,
`TMS_MT_PROVIDER` (`none|libretranslate|mock`), `TMS_MT_URL`, `TMS_MT_API_KEY`,
`TMS_FUZZY_MIN_SCORE`, `TMS_ANALYSIS_*` (веса котировки), `TMS_LQA_*`
(штрафы minor/major/critical и порог приемки LQA-оценки), `TMS_RATE_CURRENCY`
(валюта новых прайс-листов по умолчанию).

### 2. Веб-клиент
```bash
cd web && npm install && npm run dev     # http://localhost:5173
```
`VITE_API_BASE` — адрес сервера (по умолчанию http://localhost:8000).

### 3. Android
Готовый APK: `mini-tms-debug.apk` (корень) или
`mobile/android/app/build/outputs/apk/debug/app-debug.apk`.
На экране входа вводится адрес сервера (`10.0.2.2` для эмулятора, IP компьютера
для телефона в той же Wi-Fi сети). Токены хранятся в SecureStore (§11).

Пересборка: `cd mobile && npx expo prebuild -p android --no-install`, затем
`cd android && JAVA_HOME=C:/Users/dolme/tools/jdk-17.0.20.1+1 ./gradlew.bat assembleDebug`.
Нюансы сборки (зеркало Maven, sdk.dir, версии) — в конце файла и в git-истории.

## Функции сверх ТЗ (второй проход развития)

Практики зрелых CAT/TMS (Trados/memoQ/XTRF), добавленные поверх обязательных требований:

- **XLIFF 2.0** (помимо обязательного 1.2): версия распознается автоматически,
  экспорт — в версии исходника; сегменты `<segment>` внутри `<unit>`,
  `<ignorable>` не переводится; inline-разметка 2.0 (`ph`/`pc`/изолированные
  пары `sc`+`ec`) нормализуется в единый профиль тегов редактора и при экспорте
  восстанавливается с атрибутами и native-кодом из исходника — совместимость
  с Phrase, Trados 2021+, memoQ (docs/formats.md).
- **CSV-импорт TM** (паритет с глоссариями): заголовок `source,target`,
  семантика upsert — как у TMX; в вебе — кнопка Import CSV рядом с Import TMX.
- **Пагинация больших ресурсов**: записи TM/TB листаются постранично
  (`limit`/`offset`, `X-Total-Count`), в вебе — «Load more»; записи за пределами
  первой страницы больше не недоступны менеджеру.
- **Биллинг**: прайс-листы организаций (ставка за слово по категориям анализа,
  валюта, минимальная сумма заказа) → котировки заданий и проектов из анализа
  объема (слова категории × ставка, практика Trados), экспорт котировки в DOCX
  для заказчика; в вебе — страницы Rates и блок Quote в дашборде проекта.
- **Доставка и закрытие цикла**: пакет доставки проекта — все сданные целевые
  файлы одним ZIP с манифестом (`GET /api/projects/{id}/deliver`, практика
  delivery package в XTRF/Plunet), и инвойс (закрывающий документ) в DOCX —
  та же математика, что в котировке, но только по заданиям в
  submitted/completed, с детерминированным номером `INV-<проект>-<дата>`;
  в вебе — карточка Delivery в дашборде проекта.
- **История правок сегмента (track changes)**: каждое изменение перевода
  фиксируется (автор/время/текст), включая пред-перевод и автопропагацию;
  в редакторе — панель History с восстановлением старой версии в черновик.
- **Отчет продуктивности переводчиков**: подтвержденные слова, принятые/
  просроченные задания, средняя LQA-оценка — данные для распределения заданий
  (страница Reports, фильтр по периоду).
- **Ведение ресурсов (maintenance)**: правка перевода и удаление записей TM
  (исходник — ключ памяти, не меняется), правка/удаление терминов TB со
  защитой от дублей — устаревший ресурс не работает против качества;
  в вебе — кнопки Edit/Delete в таблицах записей на странице TM/TB.
- **Гигиена аккаунта**: смена пароля с подтверждением текущего
  (`POST /api/change-password`, PBKDF2 200k) и защита логина от подбора —
  скользящее окно неудачных попыток на пару (логин, IP) с 429 и Retry-After;
  в вебе — кнопка Password в шапке.
- **Резервная копия организации**: полный JSON-дамп (проекты, задания, сегменты,
  TM/TB, прайс-листы, LQA, комментарии) одной кнопкой — аварийное восстановление
  и переносимость данных; хеши паролей не выгружаются.
- **SPA одним URL из коробки**: раздаваемый бэкендом веб-клиент обращается к API
  того же происхождения без ручного ввода адреса (vite dev по-прежнему на 5173).

## Осознанные ограничения MVP (отклонения/отложено)

- **Push (FCM/APNs)** не подключен: требуется Google-проект и ключи; реализован
  центр уведомлений + WS-доставка (ТЗ прямо разрешает: push не единственный
  канал) и интерфейс-заглушка в `services/notify.py`.
- **Счетчик неудачных логинов** — в памяти процесса (скользящее окно 15 мин):
  перезапуск сбрасывает, для нескольких инстансов нужен внешний сторедж
  (Redis); смена пароля не отзывает уже выданные JWT (stateless-токены).
- **Локальные напоминания** на мобильном — через центр уведомлений при открытии
  приложения (без фоновых push).
- **Шифрование локального кэша** документов — отложено; токены в SecureStore,
  черновики в AsyncStorage приложения.
- **VoiceOver/TalkBack** — базовые accessibility-метки на ключевых элементах;
  глубокий аудит отложен.
- Подсчет слов и сегментация — правила MVP (docs/formats.md), требуют
  утверждения (§14 ТЗ).
- MT-провайдер LibreTranslate — публичный сервис может быть недоступен;
  редактор не блокируется.

## Нюансы сборки Android на этой машине

- `mobile/.m2repo/` — локальное зеркало `react-android`/`hermes-android`
  (Maven Central в этой сети обрывает большие загрузки); подключено официальным
  свойством `react.internal.mavenLocalRepo` в `android/gradle.properties`.
- `sdk.dir` в `local.properties` — только прямые слеши (`C:/...`).

  который несовместим с Compose Compiler expo-modules-core (нужен 1.9.25).
